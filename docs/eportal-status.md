# Dr.COM 校园网状态查询协议（chkstatus）

`chkstatus` 用于查询当前请求设备的接入信息和校园网认证状态。登录、注销前通过它取得设备 IPv4 等参数；后台也通过它判断是否需要重新认证。

本文区分已知请求地址与当前 Rust 客户端的解析约定。字段兼容规则来自 `crates/wlan-api/src/client.rs`，示例为合成数据，不是真实门户响应，也不表示服务端一定返回所有字段。本次文档补充未访问真实校园网门户。

## 1. 请求地址和参数

```http
GET http://172.18.254.6/drcom/chkstatus?callback=dr1&v=1234
```

| 项目 | 当前客户端行为 |
| --- | --- |
| 方法 | `GET`，用于查询，不提交登录或注销操作 |
| 地址 | `http://172.18.254.6/drcom/chkstatus`，HTTP 默认端口 `80` |
| `callback` | 固定为 `dr1`，用于识别 JSONP 包装 |
| `v` | 使用当前 Unix 毫秒时间戳作为变化参数，意图避免缓存；`1234` 是已知请求结构中的示例值 |
| 账号和密码 | 查询不携带账号、密码，也不添加 `user_account` / `user_password` |
| Cookie | 当前客户端不启用 Cookie 存储，也不主动设置 Cookie |

查询端口 `80` 与登录、注销接口的 `801` 不同。当前客户端直接访问此 IP，禁用应用层代理并禁止自动跟随重定向；没有请求其他网站，也没有进行外网测速。系统路由或 VPN 仍可能影响实际访问路径。

参数是否可以省略、是否存在其他鉴权要求，尚未通过服务端验证；表格记录的是客户端发送方式。

## 2. 响应包装

客户端接受以下两种形式：

```javascript
dr1({"v46ip":"10.0.0.12","online":1});
```

```json
{"v46ip":"10.0.0.12","online":1}
```

以上为合成示例。客户端只解析 JSON 对象，不执行 JavaScript。JSONP 回调必须为 `dr1`；其他回调、数组、额外脚本、无效 JSON 或非 UTF-8 内容会报协议错误。

## 3. 当前客户端识别的字段

以下别名按表内顺序查找。普通接入信息字段取第一个非空字符串或数字，数字转换为字符串；这套兼容规则不代表所有别名都已在本校门户响应中出现。

| 信息 | 接受的字段名（按优先级） | 缺失时的行为 |
| --- | --- | --- |
| 设备 IPv4 | `v46ip`、`v4ip`、`userip`、`user_ip`、`wlan_user_ip` | 报错，不能继续登录或注销 |
| 认证状态 | `online`，不存在时才读取 `is_login` | 返回 `Unknown`，见下一节 |
| 设备 IPv6 | `wlan_user_ipv6`、`myv6ip` | 空字符串 |
| 设备 MAC | `wlan_user_mac`、`mac` | 空字符串 |
| VLAN | `wlan_vlan_id`、`vlan` | `1` |
| 接入控制器 IP | `wlan_ac_ip`、`ac_ip` | 状态中保留为空；登录、注销构造请求时回退到配置值，默认 `172.18.255.6` |
| 接入控制器名称 | `wlan_ac_name`、`acname` | 状态中保留为空；登录、注销构造请求时回退到配置值，默认 `NAS` |

IPv4 必须能解析，且不能为未指定地址 `0.0.0.0`、广播地址 `255.255.255.255` 或组播地址。即使响应包含在线标志，没有有效 IPv4 也会报错。IPv4 只校验优先选中的值，不会在该值无效时继续尝试后面的别名。

## 4. 认证状态如何判断

认证标志首先取 `online`；只有该键不存在时才取 `is_login`。如果 `online` 已存在但为 `null` 或不支持的值，结果为 `Unknown`，不会再改读 `is_login`。

| 认证标志的值 | `AuthState` | 含义 |
| --- | --- | --- |
| `true`、`1`、`"1"` | `Online` | 门户明确表示已认证 |
| `false`、`0`、`"0"` | `Offline` | 门户明确表示未认证 |
| 缺失、`null` 或其他值 | `Unknown` | 无法根据当前规则判断 |

`result=1`、HTTP `200`、存在设备 IP，都不能单独证明已认证。登录、注销接口使用的 `result` 成功判断不能直接套到状态查询上。

合成的离线响应：

```javascript
dr1({"userip":"10.0.0.12","online":0});
```

合成的未知状态响应：

```javascript
dr1({"v46ip":"10.0.0.12","result":1});
```

第二个例子能提供设备 IP，但缺少认证标志，所以客户端返回 `Unknown`。

这项检查针对校园网认证，不证明 DNS 或外部网站可用。设备连着 Wi-Fi、门户认证在线、外网可访问，是不同的状态。

## 5. 登录、注销和后台检查如何使用它

- **登录**：`Client::login()` 先查询状态，获取新鲜的设备 IP 和接入信息，再调用登录接口。
- **注销**：`Client::logout()` 先查询状态，再构造注销请求；查询失败时不提交注销。
- **后台**：先确认当前连接的是 `Student_CX`，再决定是否查询。手动暂停、凭据被拒绝或尚未到重试时间时跳过门户请求。

后台正常情况下每 `30` 秒检查一次，并监听操作系统网络事件。收到不改变连接会话的网络事件时，不会一律追加 HTTP 请求。Linux 通过 NetworkManager 的设备类型、激活状态和 SSID 识别目标连接。

后台取得状态后：

| 查询结果 | 后台行为 |
| --- | --- |
| `Online` | 结束本轮并清除失败退避；不打印新的“登录成功”日志 |
| `Offline` | 再确认 Wi-Fi 会话没有变化，然后尝试登录 |
| `Unknown` | 刚接入、尚未成功认证的连接允许尝试登录；成功后的普通检查不会据此重新登录 |
| 查询报错 | 本轮结束，记录失败阶段及重试等待时间，不把报错当作 `Offline`；首次接入的临时网络错误允许有限快速重试 |

当前后台先调用一次 `status()`；若决定登录，随后 `login()` 内还会重新查询状态。因此正常在线的一轮通常只有一次状态请求，需要登录的一轮通常是两次状态查询加一次登录请求。

“校园网登录成功”日志来自登录接口返回成功，本轮没有紧接着再发一次状态查询来确认认证状态。

## 6. 超时、首次接入和重试

当前请求设置：

| 限制 | 值 |
| --- | --- |
| 连接超时 | `3` 秒 |
| 单次 HTTP 请求总超时 | 默认 `8` 秒 |
| 响应正文上限 | `64 KiB` |
| 后台整轮检查超时 | `60` 秒，包含读取本地状态、凭据和网络请求等步骤 |

Linux 检查要求 NetworkManager 报告设备已激活（`State=100`）。这通常意味着本地连接配置已经完成，但不能保证校园门户此刻已经能够处理请求。网络事件后的 `400` 毫秒等待用于合并连续通知，不是门户就绪探测；后台启动时也没有固定的门户预热等待。

错误示例：

```text
本次检查未完成，1 秒后重试：校园网状态查询失败: 网络请求失败: error sending request: error sending request: client error (SendRequest): connection closed before message completed
```

这表示 HTTP 消息尚未完成时连接已关闭。首次接入时门户或接入链路尚未稳定是可能原因；服务端关闭连接等情况也可能产生相同错误。仅凭该错误不能确定根因，也不能证明认证已经失效。

请求错误会标明阶段：`校园网状态查询失败`、`校园网登录请求失败` 或 `校园网注销请求失败`。即使状态查询发生在 `login()` 或 `logout()` 内部，也保留状态查询阶段。请求地址中的账号和密码不会进入传输错误日志；重复的错误文字来自逐层输出错误链。

首次接入、尚未成功取得状态响应时，状态查询的连接、发送、读取、超时或 HTTP `5xx` 错误，最多快速重试三次，等待依次为 `1`、`2`、`4` 秒。每次等待从本次请求失败后计算；请求本身仍受超时限制，所以不保证在七秒内完成认证。任何有效状态响应都会结束本次连接的快速重试阶段。

快速重试用尽后，连续失败的常规等待依次为 `30`、`60`、`120`、`240`、`300` 秒，此后保持 `300` 秒。格式不支持、缺少有效 IP、HTTP `4xx`、本地凭据读取失败及登录请求失败等不进入快速重试。账号密码被拒绝时仍暂停自动重试。认证成功、连接会话变化或控制状态修订会清除常规退避；重新接入会重新获得快速重试机会。

后台同时等待正常检查周期和独立的重试截止时间，不会为了凑下一个 `30` 秒周期额外推迟重试。例如常规检查在 `08:00:11` 失败、等待 `30` 秒时，`08:00:35` 的周期会跳过请求，`08:00:41` 则直接唤醒重试，不再等到 `08:01:05`。首次接入的快速重试则最早在 `08:00:12` 唤醒。

每次重试仍需重新检查目标 Wi-Fi、手动暂停状态及凭据拒绝状态。到期的重试定时器只触发一次；即使本轮因暂停而跳过，也不会在后台形成忙循环。等待可被网络事件、手动控制和停止信号打断。

## 7. 尚未确认的服务端行为

- 本校不同认证状态、线路和接入阶段的真实完整响应，以及实际使用的认证标志。
- 查询参数的最小集合、缓存行为，以及 IP、MAC、VLAN 等字段何时更新。
- 刚接入 Wi-Fi 后门户可用的时延、提前关闭连接的具体原因，以及 HTTP 连接复用兼容性。
- 门户版本变化时，认证状态字段和错误响应是否保持一致。

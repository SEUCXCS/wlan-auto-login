# Dr.COM 校园网状态查询协议（chkstatus）

`chkstatus` 用于查询当前请求设备的接入信息和校园网认证状态。登录、注销前通过它取得设备 IPv4 等参数；后台也通过它判断是否需要重新认证。

2026-09-23 经用户授权只读查询 `chkstatus`，收到 HTTP 200 和 `result=1` 的在线响应，实际没有 `online` / `is_login` 字段。同时只读核对门户静态脚本：[`a41.js`](http://172.18.254.6/a41.js) 的 `checkStatus` 明确以 `result=0` 判断离线、`result=1` 判断在线；[`a42.js`](http://172.18.254.6/a42.js) 的 `portal_login_err` 给出了登录拒绝码含义。本次未发送真实登录或注销请求。下文在线示例已脱敏；离线含义来自门户脚本，尚未通过主动断网或注销实测。

## 1. 请求地址和参数

```http
GET http://172.18.254.6/drcom/chkstatus?callback=dr1&v=1234
```

| 项目 | 当前客户端行为 |
| --- | --- |
| 方法 | `GET`，用于查询，不提交登录或注销操作 |
| 地址 | `http://172.18.254.6/drcom/chkstatus`，HTTP 默认端口 `80` |
| `callback` | 固定为 `dr1`，用于识别 JSONP 包装 |
| `v` | 使用当前 Unix 毫秒时间戳作为变化参数，意图避免缓存；`1234` 是已知请求结构中的示例值 |
| 账号和密码 | 查询不携带账号、密码，也不添加 `user_account` / `user_password` |
| Cookie | 当前客户端不启用 Cookie 存储，也不主动设置 Cookie |

查询端口 `80` 与登录、注销接口的 `801` 不同。当前客户端直接访问此 IP，禁用应用层代理并禁止自动跟随重定向；没有请求其他网站，也没有进行外网测速。系统路由或 VPN 仍可能影响实际访问路径。

使用 curl 时必须给整个 URL 加引号：

```sh
curl --noproxy '*' --connect-timeout 5 --max-time 15 'http://172.18.254.6/drcom/chkstatus?callback=dr1&v=1234'
```

否则 shell 会将 `&` 解释为后台执行符，实际请求只到 `callback=dr1`，而 `v=1234` 成为 shell 变量赋值；终端中的 `[1] 进程号` 就是这个原因。`curl: (52) Empty reply from server` 则表示对端没有返回 HTTP 响应就关闭了连接，不能仅凭它认定是缺少 `v` 引起的。后续一次查询成功也不表示之前的空响应不存在。

参数是否可以省略、是否存在其他鉴权要求仍未验证。

## 2. 响应包装

客户端接受以下两种形式：

```javascript
dr1({"result":1,"v46ip":"10.0.0.12","uid":"2026000000","time":6364,"flow":8388608});
```

```json
{"result":1,"v46ip":"10.0.0.12","uid":"2026000000"}
```

以上为脱敏、精简的在线示例；完整结构见 [回归测试样本](../crates/wlan-api/tests/fixtures/chkstatus-online.jsonp)。客户端只解析 JSON 对象，不执行 JavaScript。JSONP 回调必须为 `dr1`；其他回调、数组、额外脚本、无效 JSON 或非 UTF-8 内容会报协议错误。

## 3. 当前客户端识别的字段

以下别名按表内顺序查找。普通接入信息字段取第一个非空字符串或数字，数字转换为字符串；这套兼容规则不代表所有别名都已在本校门户响应中出现。

| 信息 | 接受的字段名（按优先级） | 缺失时的行为 |
| --- | --- | --- |
| 设备 IPv4 | `v46ip`、`v4ip`、`userip`、`user_ip`、`wlan_user_ip` | 报错，不能继续登录或注销 |
| 认证状态 | 本校使用 `result`；另兼容优先读取 `online` / `is_login` | 返回 `Unknown`，见下一节 |
| 设备 IPv6 | `wlan_user_ipv6`、`myv6ip` | 空字符串 |
| 设备 MAC | `wlan_user_mac`、`mac` | 空字符串 |
| VLAN | `wlan_vlan_id`、`vlan` | `1` |
| 接入控制器 IP | `wlan_ac_ip`、`ac_ip` | 状态中保留为空；登录、注销构造请求时回退到配置值，默认 `172.18.255.6` |
| 接入控制器名称 | `wlan_ac_name`、`acname` | 状态中保留为空；登录、注销构造请求时回退到配置值，默认 `NAS` |

IPv4 必须能解析，且不能为未指定地址 `0.0.0.0`、广播地址 `255.255.255.255` 或组播地址。即使响应包含在线标志，没有有效 IPv4 也会报错。IPv4 只校验优先选中的值，不会在该值无效时继续尝试后面的别名。

## 4. 认证状态如何判断

本校 `chkstatus` 的状态标志就是 `result`，无需出现名称为 `online` 的字段：

| `result` 的值 | `AuthState` | 含义 |
| --- | --- | --- |
| `1`、`"1"` | `Online` | 当前设备已认证 |
| `0`、`"0"` | `Offline` | 当前设备未认证 |
| 缺失、`null` 或其他值 | `Unknown` | 不能确定，不自动提交登录 |

兼容其他响应时，若存在 `online` 则优先使用它，否则读取 `is_login`；这两个字段接受布尔值或数值/字符串 `0`、`1`。存在但无法识别的显式标志仍为 `Unknown`，不会被 `result` 覆盖。

这条 `result` 规则限定于 `chkstatus`，依据门户自己的状态判断代码；HTTP `200` 或存在 IP 本身不证明认证成功。登录、注销接口里的 `result` 表示该操作的执行结果。

按静态脚本构造的离线示例：

```javascript
dr1({"v46ip":"10.0.0.12","result":0});
```

未知格式示例：

```javascript
dr1({"v46ip":"10.0.0.12","result":99});
```

这项检查针对校园网认证，不证明 DNS 或外部网站可用。设备连着 Wi-Fi、门户认证在线、外网可访问，是不同的状态。

## 5. 登录、注销和后台检查如何使用它

- **登录**：`Client::login()` 先查询状态；已在线时返回 `LoginOutcome::AlreadyOnline`，不重复提交凭据。其他有效状态下再调用登录接口，成功返回 `LoginOutcome::Authenticated`。前者不表示本次提供的账号、密码或线路经过了验证。
- **注销**：`Client::logout()` 先查询状态，再构造注销请求；查询失败时不提交注销。
- **后台**：先确认当前连接的是 `Student_CX`，再决定是否查询。手动暂停、凭据被拒绝或尚未到重试时间时跳过门户请求。

后台确认认证在线后每 `4` 分钟检查一次；刚登录成功后先等待 `30` 秒查询确认，未知状态和未连接目标网络时保留 `30` 秒的常规检查间隔。后台持续监听操作系统网络事件。收到不改变连接会话的网络事件时，不会一律追加 HTTP 请求。Linux 通过 NetworkManager 的设备类型、激活状态和 SSID 识别目标连接。

后台取得状态后：

| 查询结果 | 后台行为 |
| --- | --- |
| `Online` | 清除失败退避，下次轮询在 4 分钟后；不重复登录，也不读取后台凭据 |
| `Offline` | 再确认 Wi-Fi 会话没有变化，然后尝试登录 |
| `Unknown` | 不自动提交登录，包括刚启动和刚接入时；继续等待后续可识别状态 |
| 查询报错 | 本轮结束，记录失败阶段及重试等待时间，不把报错当作 `Offline`；首次接入的临时网络错误允许有限快速重试 |

当前后台先调用一次 `status()`；若决定登录，随后 `login()` 内还会重新查询状态。因此正常在线的一轮通常只有一次状态请求，需要登录的一轮通常是两次状态查询加一次登录请求；第二次查询若发现已在线，会取消登录提交。

“校园网登录成功”日志来自登录接口返回成功，随后在 30 秒后查询确认。确认在线才切换到 4 分钟间隔；CLI 检测到已经在线时会单独提示，不宣称本次凭据认证成功。

## 6. 超时、首次接入和重试

当前请求设置：

| 限制 | 值 |
| --- | --- |
| 连接超时 | `3` 秒 |
| 单次 HTTP 请求总超时 | 默认 `8` 秒 |
| 响应正文上限 | `64 KiB` |
| 后台整轮检查超时 | `60` 秒，包含读取本地状态、凭据和网络请求等步骤 |

Linux 检查要求 NetworkManager 报告设备已激活（`State=100`）。这通常意味着本地连接配置已经完成，但不能保证校园门户此刻已经能够处理请求。网络事件后的 `400` 毫秒等待用于合并连续通知，不是门户就绪探测；后台启动时也没有固定的门户预热等待。

错误示例：

```text
本次检查未完成，1 秒后重试：校园网状态查询失败: 网络请求失败: error sending request: error sending request: client error (SendRequest): connection closed before message completed
```

这表示 HTTP 消息尚未完成时连接已关闭。首次接入时门户或接入链路尚未稳定是可能原因；服务端关闭连接等情况也可能产生相同错误。仅凭该错误不能确定根因，也不能证明认证已经失效。

请求和操作结果解析错误都会标明阶段：`校园网状态查询失败`、`校园网登录请求失败` 或 `校园网注销请求失败`。即使状态查询发生在 `login()` 或 `logout()` 内部，也保留状态查询阶段。请求地址中的账号和密码不会进入传输错误日志；重复的错误文字来自逐层输出错误链。

首次接入、尚未成功取得状态响应时，状态查询的连接、发送、读取、超时或 HTTP `5xx` 错误，最多快速重试三次，等待依次为 `1`、`2`、`4` 秒。每次等待从本次请求失败后计算；请求本身仍受超时限制，所以不保证在七秒内完成认证。任何有效状态响应都会结束本次连接的快速重试阶段。

快速重试用尽后，连续失败的常规等待依次为 `30`、`60`、`120` 秒，此后保持 `120` 秒。格式不支持、缺少有效 IP、HTTP `4xx`、本地凭据读取失败及登录请求失败等不进入快速重试。账号密码被拒绝时仍暂停自动重试。认证成功、连接会话变化或控制状态修订会清除常规退避；重新接入会重新获得快速重试机会。

后台只等待下一次检查或重试的截止时间，在线等待期间没有额外的 30 秒周期唤醒。例如请求在 `08:00:11` 失败、退避 30 秒时，直接在 `08:00:41` 唤醒；确认在线后则等待 4 分钟。截止时间从本轮结束后计算，请求耗时不包含在等待间隔内。同一连接上重复的网络通知不会缩短或延长既定等待，新 Wi-Fi 会话或手动登录则清除等待并触发检查。

每次重试仍需重新检查目标 Wi-Fi、手动暂停状态及凭据拒绝状态。到期的重试定时器只触发一次；即使本轮因暂停而跳过，也不会在后台形成忙循环。等待可被网络事件、手动控制和停止信号打断。

## 7. 尚未确认的服务端行为

- 不同线路、离线状态和接入阶段的完整响应；当前已核对在线响应及门户脚本中的状态标志。
- 查询参数的最小集合、缓存行为，以及 IP、MAC、VLAN 等字段何时更新。
- 刚接入 Wi-Fi 后门户可用的时延、提前关闭连接的具体原因，以及 HTTP 连接复用兼容性。
- 门户版本变化时，认证状态字段和错误响应是否保持一致。

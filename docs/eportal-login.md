# ePortal 校园网登录协议

本文记录 WLAN 自动登录功能依赖的基础请求结构，后续实现、测试和排障均应以这里整理的内容为基准。

> 当前仅根据已知请求结构整理协议，未实际调用登录接口，也未验证响应字段、返回码及异常场景。本文中的“已确认”仅表示该值或行为已由现有请求结构证明，不代表所有环境永久不变。

## 1. 涉及的服务地址

| 用途 | 地址 |
| --- | --- |
| ePortal 登录接口 | `http://172.18.254.6:801/eportal/` |
| 当前设备状态查询接口 | `http://172.18.254.6/drcom/chkstatus` |

登录请求中的接入控制器信息是：

| 参数 | 值 |
| --- | --- |
| `wlan_ac_ip` | `172.18.255.6` |
| `wlan_ac_name` | `NAS` |

## 2. 登录流程

自动登录至少需要两个步骤：

1. 请求状态查询接口，获取当前设备的校园网 IP。
2. 将该 IP 作为 `wlan_user_ip`，连同学号和密码请求 ePortal 登录接口。

```text
查询当前设备状态
        |
        v
解析 wlan_user_ip
        |
        v
构造 ePortal 登录请求
        |
        v
提交登录
```

## 3. 查询当前设备 IP

### 请求

```http
GET http://172.18.254.6/drcom/chkstatus?callback=dr1&v=1234
```

| 参数 | 是否必需 | 说明 |
| --- | --- | --- |
| `callback` | 是 | 使用 `dr1`，表明接口采用 JSONP 风格的回调包装。 |
| `v` | 是 | 已知请求示例使用 `1234`；当前客户端使用 Unix 毫秒时间戳。 |

### 用途

从响应中取得当前设备的校园网 IP，并写入后续登录请求的 `wlan_user_ip` 参数。当前客户端识别的 IP 字段、认证状态、响应示例及后台检查行为见 [Dr.COM 校园网状态查询协议](./eportal-status.md)。该文档区分客户端兼容规则与尚待确认的服务端行为。

## 4. ePortal 登录请求

### 请求结构

以下 URL 中的尖括号部分需要替换为真实值：

```http
GET http://172.18.254.6:801/eportal/?c=Portal&a=login&callback=dr1&login_method=1&user_account=<学号><账号后缀>&user_password=<密码>&wlan_user_ip=<当前设备校园网IP>&wlan_user_ipv6=&wlan_user_mac=&wlan_ac_ip=172.18.255.6&wlan_ac_name=NAS&jsVersion=3.3.3&v=1234
```

### 登录参数

| 参数 | 示例值 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `c` | `Portal` | 是 | 固定值。 |
| `a` | `login` | 是 | 固定值，表示登录操作。 |
| `callback` | `dr1` | 是 | 固定值，与状态查询接口一致。 |
| `login_method` | `1` | 是 | 固定值。 |
| `user_account` | `<学号><账号后缀>` | 是 | 由学号和所选服务类型的后缀组成，见下表。 |
| `user_password` | `<密码>` | 是 | 用户的校园网密码。 |
| `wlan_user_ip` | `<当前设备校园网IP>` | 是 | 使用状态查询接口取得的 IP。 |
| `wlan_user_ipv6` | 空 | 是 | 当前请求中保留为空。 |
| `wlan_user_mac` | 空 | 是 | 当前请求中允许为空。 |
| `wlan_ac_ip` | `172.18.255.6` | 是 | 固定接入控制器 IP。 |
| `wlan_ac_name` | `NAS` | 是 | 固定接入控制器名称。 |
| `jsVersion` | `3.3.3` | 是 | 当前接口版本标识。 |
| `v` | `1234` | 是 | 当前请求结构中使用的版本或缓存参数。 |

### 账号类型与后缀

三种服务使用同一个登录接口，仅在 `user_account` 后缀上不同：

| 服务类型 | `user_account` 格式 | 示例（学号 `2026000000`） |
| --- | --- | --- |
| 临时免费 1 | `<学号>@dianxin` | `2026000000@dianxin` |
| 内网 | `<学号>@xyw` | `2026000000@xyw` |
| 免费 2 | `<学号>@free` | `2026000000@free` |

URL 编码时，`@` 可以写为 `%40`，例如 `2026000000%40dianxin`。

### 参数替换示例（临时免费 1）

假设：

- 学号为 `2026000000`
- 密码为 `example-password`
- 状态查询得到的校园网 IP 为 `10.0.0.100`

则逻辑上的登录地址为：

```text
http://172.18.254.6:801/eportal/?c=Portal&a=login&callback=dr1&login_method=1&user_account=2026000000%40dianxin&user_password=example-password&wlan_user_ip=10.0.0.100&wlan_user_ipv6=&wlan_user_mac=&wlan_ac_ip=172.18.255.6&wlan_ac_name=NAS&jsVersion=3.3.3&v=1234
```

以上只是参数替换示意，不是可复用的真实凭据，也不应在项目仓库中保存真实密码。

## 5. 构造请求时的要求

1. 先执行状态查询，再执行登录，不建议直接猜测或复用其他设备的 `wlan_user_ip`。
2. 所有查询参数都应进行 URL 编码，尤其是密码内的 `@`、`&`、`=`、`+` 等字符。
3. `user_account` 必须根据所选服务类型选择 `@dianxin`、`@xyw` 或 `@free`；其中的 `@` 编码为 `%40` 更稳妥，服务端通常也能接受未编码形式。
4. `wlan_user_ipv6` 和 `wlan_user_mac` 在当前已知请求中留空即可。
5. 学号、密码等敏感信息必须来自本地配置、环境变量或安全凭据存储，不能写入仓库。
6. 实现层应统一维护主机、接入控制器和固定参数，避免在多个位置重复拼接请求。

## 6. 当前客户端的在线与拒绝处理

2026-09-23 只读查询状态并核对门户 `a41.js` / `a42.js` 后，客户端按以下规则处理：

- `chkstatus.result=1` 表示当前设备已在线。`Client::login()` 返回 `LoginOutcome::AlreadyOnline`，不提交登录；CLI 明确说明本次提供的凭据和线路没有在线验证。要切换当前会话的账号或线路，应先显式注销。
- 发送登录请求并收到成功结果时，返回 `LoginOutcome::Authenticated`。
- `result` 为失败且缺少文字说明时，仍读取 `ret_code`，同时保留失败阶段和数值码；`ret_code=2` 本身不会被当作本次凭据验证成功。

| `ret_code` | 门户脚本定义 |
| --- | --- |
| `1` | 账号或密码不正确；后台暂停自动重试 |
| `2` | 终端 IP 已经在线 |
| `3` | 系统繁忙 |
| `4` | 未知错误 |
| `5` / `6` | REQ_CHALLENGE 失败 / 超时 |
| `7` / `8` | Radius 认证失败 / 超时 |
| `9` / `10` | Radius 下线失败 / 超时 |
| `11` | 其他错误 |
| `998` | Portal 协议参数不完整 |

这些返回码来自门户静态脚本，不是通过真实登录失败试验获得的。未知错误码会保留数值供排障，错误消息中的账号、密码和终端控制字符仍会清理。

## 7. 尚未确认的事项

以下内容需要在后续实现阶段通过安全、受控的真实请求补充：

- 不同线路和离线时的完整状态响应（已记录一次脱敏在线响应）；
- 登录成功与失败时的响应结构和状态码；
- 是否需要 Cookie、会话或额外请求头；
- 密码或账号的额外加密逻辑是否存在；
- IP 变化、重复登录、错误密码和接口超时的处理方式。

在以上内容得到验证前，实现应把接口视为当前网络环境下的已知协议，而不是完整的通用 ePortal 规范。
